## 能源解决方案 Agent（energy_solution_agent）毛里塔尼亚矿区项目分析

### 项目背景
- 地点：毛里塔尼亚（23.196941 / -11.959593）
- 负荷：破碎系统 18MW（20h/天）+ 磨选系统 44.46MW（24h/天）= 总峰值 62.46MW
- 日能耗 ~1427 MWh，年耗 521,870 MWh
- 需求：一期光储 + 72MW风电预留二期

### 核心结论：agent 存在设计缺陷，不适合直接用于可研

#### 发现的问题

**问题1：储能规模判断逻辑有缺陷**
- 微电网场景推荐 40MW/240MWh，但年等效满循环 **0次**，储能基本死掉
- 钢铁厂场景推荐 30MW/150MWh，年等效满循环 **0.226次**，依然极少使用
- **根因**：agent 的设计目标是"最大化新能源覆盖率"，不是"负荷驱动+储能循环"
- 新能源规模过大（光伏230MW + 风电72MW = 年发电781GWh，而负荷只有522GWh），储能根本没有参与调度空间

**问题2：风电规模不是固定72MW**
- agent 有自己的规模计算逻辑（annual_load × 0.15 / (8760 × capacity_factor)），会覆盖用户输入
- 绕过方法：直接给 `hourly_generation_profile_kw`，峰值设为72000kW

**问题3：储能循环次数不是约束条件**
- agent 没有 `storage.min_daily_cycles` 参数
- 用户期望：储能每天至少1个完整循环（365次/年）
- 实际结果：0.226次/年，严重偏低

**问题4：光伏规模过度**
- 230.77 MWp 是"最大化新能源"目标驱动，不是负荷驱动
- 应该基于负荷需求和储能调度需求反推，而不是先定新能源规模

#### 场景适配性对比

| 场景 | 储能功率 | 储能能量 | 年循环次数 | 碳基线 |
|------|---------|---------|-----------|--------|
| microgrid | 40MW | 240MWh | **0次** | 168 tCO2e（失真）|
| steel_factory | 30MW | 150MWh | **0.226次** | 476,000 tCO2e（较合理）|

**推荐场景**：steel_factory（钢铁厂），比 microgrid 更适合矿业项目

### 改进建议（待用户确认后执行）

**改动位置**：`agents/energy_solution_agent/energy_solution_agent/src/engine.py` 的 `estimate_storage` 函数（约第438行）

**改动方案**：在 estimate_storage 之后加循环检查，如果年循环<365，放大储能重新跑调度

```python
# 强制储能每天至少1个完整循环
min_storage_cycles_per_year = 365
while actual_cycles < min_storage_cycles_per_year and放大次数 < 3:
    放大储能规模
    重新跑调度
```
