## DeepSeek 模型修复记录

### 问题描述
- `/model deepseek` 切换时报错：`400 The reasoning_content in the thinking mode must be passed back to the API`
- 原因：OpenClaw 的流式响应在处理 DeepSeek 的 `reasoning_content` 时出错

### 修复过程
1. 添加 `reasoning: false` 到 deepseek 模型配置 → 无效
2. 关闭 feishu streaming → 无效
3. 添加 `thinkingFormat: none` → 配置无效（允许值只有 openai/openrouter/zai/qwen/qwen-chat-template）
4. 最终方案：**删除 deepseek-v4-flash，只保留 deepseek-chat**

### 最终配置
```json
{
  "models": {
    "providers": {
      "deepseek": {
        "baseUrl": "https://api.deepseek.com/v1",
        "apiKey": "sk-829a69f62a054d0f9a9ff3d79d7909b0",
        "api": "openai-completions",
        "models": [{
          "id": "deepseek-chat",
          "name": "DeepSeek-Chat (兼容模式)",
          "reasoning": false,
          "input": ["text", "image"],
          "contextWindow": 640000,
          "maxTokens": 8192
        }]
      }
    }
  },
  "agents": {
    "defaults": {
      "model": {"primary": "deepseek/deepseek-chat"},
      "models": {
        "deepseek/deepseek-chat": {"alias": "deepseek"}
      }
    }
  }
}
```

### 重要结论
- `deepseek-chat` 和 `deepseek-v4-flash` 实际是同一个模型（API 层面）
- DeepSeek API **始终返回 `reasoning_content`**，无论是否开启思考模式
- 子 Agent 测试时 deepseek-chat 无思考块，但主会话因历史上下文可能有差异
- `/new` 开新会话可清除历史影响

### 已知问题
- DeepSeek 回复时会显示思考内容（reasoning_content），这是模型特性，非配置错误
- MiniMax 没有这个问题

### GPT-5.4 vs GPT-5.4-mini
- 5.4: 上下文1.05M token，$2.50输入/$15输出每1M
- 5.4-mini: 上下文128K，更便宜更低延迟，适合数据分析/文案
- 结论：普通Excel分析用5.4-mini绑绑有余

### Token 消耗知识点
- 推理/思考过程不占上下文窗口（模型内部GPU运算）
- 只有输入（文件+问题）和输出（回复）占token
- 普通数据分析：输入是大头，输出很小
- 广播专员是纯CLI工具，不走AI模型，不吃token

### Session 模型
- 不同session可以用不同模型，互不影响
- crontab任务用 agents.defaults.model.primary（已改成minimax）
- 用户手动 /model 只影响当前session
