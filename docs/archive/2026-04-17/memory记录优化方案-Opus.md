# Memory 每日记录优化方案（Opus 架构版）

*by Opus 4.6 via acpx 本地 CC — 2026-04-16*

---

## 背景

memory search 已接管全文检索，daily memory 文件只需改进**内容质量**，专注可读性，不再承担检索功能。

---

## 1. 格式优化

### 当前问题
原始聊天记录直接堆叠，噪音极高——包含 OpenClaw internal context、exec output、系统消息、完整对话引用。

### 优化方案：只记结构化摘要，不记原文

```markdown
# 2026-04-16

## 决策 (DECISION)
- [标签] 一句话描述 + 原因

## 任务 (TASK)
- [完成] xxx
- [进行中] xxx

## 知识 (LEARNED)
- 一句话新知识点

## 待跟进
- xxx @owner
```

### 关键原则
- **抛弃对话转录模式**——memory search 已能全文检索，无需在 daily memory 里复述对话
- 每日记忆文件的价值 = 提炼「决策、结论、待办」三类高密度信息
- 删除所有噪音：internal context、exec output、系统消息、`[[reply_to_current]]`、引用链

---

## 2. 触发时机

### 当前问题
08:00 / 16:00 / 23:00 固定时段触发，与实际工作节奏脱节——可能在空闲时无意义触发，关键决策时又刚好错过。

### 优化方案：事件驱动 + 日终兜底

| 触发类型 | 时机 | 说明 |
|----------|------|------|
| **主触发** | 会话自然结束时 | 用户说"好了"/静默超30分钟 |
| **次触发** | 重要里程碑完成时 | 关键任务/决策出现 |
| **兜底** | 每日 21:00 | 保证每天至少一条 |

**取消** 08:00 / 16:00 / 23:00 的固定自动消息提取。

---

## 3. 去重机制

### 方案
1. **内容哈希去重**：写入前对新增内容（决策/任务/知识）做 hash，已存在则跳过
2. **diff 覆盖保护**：已记录的决策不覆盖，只追加新条目
3. **锚点分段**：每个 section（决策/任务/知识）独立去重，同一决策不会被重复记录

---

## 实施优先级

| 优先级 | 改动 | 预计效果 |
|--------|------|----------|
| **P0 立即** | 停止 08:00 / 16:00 定时提取 | 减少80%噪音 |
| **P1 本周** | 改造记录生成逻辑：原始消息→结构化摘要 | 内容质量提升 |
| **P2 短期** | 实现内容哈希去重 | 消除重复记录 |
| **P3 中期** | 事件驱动触发替代定时触发 | 记录更及时 |

---

## 收益评估

- 每日记忆文件可读性：差 → 好
- 重复记录率：有效消除
- 月度整理耗时：大幅减少（memory search 接管检索后 daily memory 专注可读性）
