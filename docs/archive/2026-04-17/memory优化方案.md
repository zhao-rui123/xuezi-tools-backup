## 一、现状分析与问题定位

### 现状

```
memory/
├── 2026-03-01.md   # 流水账，内容混杂
├── 2026-03-02.md   # 精华，包含重要决策
├── ...
├── 2026-04-15.md   # 极简，仅几句话
archive_summary.md  # 每月25号手工整理
MEMORY.md           # 长期记忆（手动维护）
```

### 痛点根因

| 痛点 | 根因 |
|------|------|
| 内容质量参差不齐 | 每日 md 无筛选标准，机器/人工都直接灌 |
| 手工整理工作量大 | 30天内容集中一天处理，无渐进积累 |
| 精华/垃圾混杂 | 缺少价值分级机制，全部等同存储 |

## 二、分层存储策略（三仓架构）

### 架构图（文字版）

```
┌─────────────────────────────────────────────────────────────┐
│                     用户对话输入                              │
└─────────────────────────┬───────────────────────────────────┘
                          ▼
┌─────────────────────────────────────────────────────────────┐
│              【第一仓】每日 Raw Store                         │
│  路径：memory/YYYY-MM-DD.md                                  │
│  规则：原始记录，完整保留，禁止删除                            │
│  内容：所有对话摘要全部写入（含流水账）                         │
│  标注：在文件头部用 YAML Front Matter 打标签                   │
│  ---                                                         │
│  importance: high/medium/low   # 重要度（系统+人工）           │
│  topics: [储能, 股票]        # 主题标签                        │

│  todos: ["TODO: 继续优化"]  # 待办记录                        │
│ 精华片段自动标记（见第四章）                                   │
└────────────┬────────────────────────────┬────────────────────┘

             ▼                             ▼
┌────────────────────────────┐  ┌────────────────────────────────┐
│  【第二仓】精华 Archive      │  │  【第三仓】长期记忆             │
│  路径：archive/            │  │  路径：MEMORY.md               │
│                             │  │                                │
│  结构：                     │  │  结构：                         │
│  archive/                   │  │  # 人物                        │
│  ├── 2026-03.md            │  │  - 雪子：自选股、偏好...        │
│  ├── 2026-04.md            │  │  # 项目                        │
│  ├── decisions.md          │  │  - 储能电站排布系统             │
│  ├── todos.md              │  │  # 决策记录                    │
│  └── topics/               │  │  - 2026-03: 决定用API方案X      │
│      ├── 储能.md           │  │  # 知识图谱                    │
│      ├── 股票.md           │  │  - 锂电池→赣锋锂业→...         │
│      └── ...               │  │                                │
│                             │  │  只保留：高价值、永久性内容      │
│  月度压缩，渐进整理           │  │  定期精简，避免膨胀             │
└────────────────────────────┘  └────────────────────────────────┘
```

### 三仓职责定义

| 仓库 | 保留周期 | 内容标准 | 维护方式 |
|------|----------|----------|----------|
| **每日 Raw** | 永久（禁止删除） | 100% 原始记录，含流水账 | 自动追加 |
| **精华 Archive** | 12 个月压缩归档 | importance=high/medium 的记录 | 自动提炼 + 月度归档 |
| **长期记忆** | 永久 | 决策、人物、项目、知识图谱 | 人工审核 + 关键触发 |

### 入仓规则

```
进入条件：
  每日 Raw    ← 100% 对话，自动写入
  精华 Archive ← 满足以下任一条件：
                  • importance: high
                  • 包含 decisions 字段
                  • 包含超过500字的技术内容
                  • 人工打标 ⭐
  长期记忆    ← 满足以下任一条件：
                  • 决策类内容（decisions）
                  • 人物特征/偏好
                  • 项目里程碑
                  • 知识体系关键节点
                  • 人工精选 ⭐⭐
```

## 三、自动精华提炼机制

### 3.1 实时标注（写入时）

在每日 md 头部 YAML Front Matter 中自动注入：

```yaml
---
date: 2026-04-16
importance: medium          # 默认 medium
topics: [储能, 股票]
decisions: []               # 空，检测到决策后追加
todos: []
essence_flag: false        # 是否已提炼精华
word_count: 3240            # 字数统计
session_count: 5            # 当日会话轮次
---
```

### 3.2 自动打分规则

```python
# importance 打分算法

def calculate_importance(content: str, metadata: dict) -> str:
    score = 0

    # 加分项
    if any(kw in content for kw in ["决定", "确定", "最终方案", "选用"]):
        score += 3        # 决策类内容
    if any(kw in content for kw in ["TODO", "待办", "要做", "下一步"]):
        score += 2        # 待办类
    if any(kw in content for kw in ["架构", "设计", "方案", "原理"]):
        score += 2        # 技术深度
    if len(content) > 2000:
        score += 1        # 长会话
    if metadata.get("session_count", 0) > 5:
        score += 1        # 多轮会话

    # 减分项
    if any(kw in content for kw in ["你好", "在吗", "几点", "天气"]):
        score -= 2        # 寒暄类
    if len(content) < 200:
        score -= 1        # 极短会话

    # 定级
    if score >= 4:
        return "high"
    elif score >= 2:
        return "medium"
    else:
        return "low"
```

### 3.3 精华片段提取

对于 `importance: high` 的每日 md，自动生成精华片段列表：

```markdown
## 💎 精华摘录

- **[决策]** 确定储能系统采用 "算法A + 人工微调" 混合方案
- **[技术]** 解决了 Vue3 响应式在动态表单中的深度监听问题
- **[待办]** 继续优化储能排布算法，下周一前出 demo
```

## 四、触发条件体系

### 4.1 触发矩阵

| 事件 | 触发动作 | 执行时机 | 方式 |
|------|----------|----------|------|
| 每日首次启动 | 打标签 + 字数统计 | 自动 | 启动脚本 |
| 长对话结束（>30分钟） | 精华片段提取 | 自动 | session-compressor |
| 每日 23:00 | importance 打分 + 精华标记 | 自动 | 每日 cron |
| 每月 25 号 | Archive 月度归档 | 手动触发 | 管理员命令 |
| 重要决策出现 | 同步写入 MEMORY.md | 半自动 | AI 推荐 + 人工确认 |
| 人工打标 ⭐ | 立即提炼到 Archive | 实时 | @助手 "标记为重要" |

### 4.2 每日 Cron 任务（23:00）

```bash
# 伪代码：每日 23:00 执行
#!/bin/bash
cd ~/.openclaw/workspace

# 1. 对今日 md 打 importance 标签
python3 scripts/memory_scorer.py

# 2. 提取精华片段（针对 high/medium）
python3 scripts/memory_essence_extractor.py

# 3. 更新 archive（high 内容）
python3 scripts/memory_archive_sync.py

# 4. 索引重建（可选，每周一次）
openclaw memory index --force
```

### 4.3 月度归档流程（每月 25 号）

```
触发 → 读取过去30天所有 md → 提取 high/medium → 合并到 archive/YYYY-MM.md
     → 清理 todos（已完成打勾，未完成保留）→ 更新 archive_summary.md
     → 压缩旧的每日 md（可选，仅作归档但保留原文）
     → openclaw memory index --force
```

## 六、收益评估

### 量化收益

| 指标 | 现状 | 优化后（预期） | 提升 |
|------|------|----------------|------|
| 精华内容识别率 | ~20%（全凭人工） | ~80%（自动+人工） | +60% |
| 月度整理耗时 | ~120 分钟（手工） | ~10 分钟（自动+人工复核） | -92% |
| Archive 可检索性 | 弱（全文搜索） | 强（按月/主题/类型分） | 显著提升 |
| 长期记忆准确率 | 依赖人工记忆 | 决策自动入 MEMORY.md | 大幅提升 |

### 定性收益

- **查找速度**：从"翻遍30天md找一条记录" → "按月/按主题秒级定位"
- **知识沉淀**：精华不再淹没在流水账中，价值被看见
- **维护负担**：从每月一次痛苦整理 → 每日小修+月度微调
- **系统健康**：清晰的层次结构，索引更高效

### 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 自动打分不准 | 精华遗漏或垃圾混入 | Phase 3 调参 + 人工抽检 |
| 脚本执行失败 | 归档缺失 | cron 日志 + 异常告警 |
| archive 目录膨胀 | 仍然混乱 | 定期（每6个月）压缩旧 archive |
| 破坏现有 memory | 索引损坏 | **操作前先备份整个 memory/ 目录** |

> ⚠️ **铁律不变**：本地 memory/*.md 禁止删除，只能归档
