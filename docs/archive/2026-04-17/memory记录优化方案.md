# Memory 每日记录优化方案

## 背景

openclaw memory search 已接管全文检索，daily memory 文件只需改进**内容质量**，专注可读性，不再承担检索功能。

---

## 1. 记录格式优化

### 当前问题
大量原始消息转储（`[[reply_to_current]]`、内部上下文块、`Exec completed`、完整对话引用），有价值内容被淹没在噪声里。

### 优化格式

```
# Memory YYYY-MM-DD

## 今日进展
- [项目/任务] 状态 + 关键结论

## 重要决策
- [决策内容] → [结论/方向]

## 经验教训
- 遇到[问题类型] → [怎么发现/怎么修]：[文件/脚本]

## 待跟进
- [未完成事项] @owner 状态
```

### 设计原则
- 只记录**合成的结论**，不记录原始消息
- 保留：决策、教训、进展、待办
- 删除：原始消息ID、引用链、`Exec completed`输出、内部上下文块
- 全文检索由 openclaw memory search 接管，daily memory 专注可读性

---

## 2. 记录时机

### 当前问题
08:00 / 16:00 / 23:00 固定时段触发，同一天多次记录，内容重复。

### 优化方案

**事件驱动为主，定时兜底为辅**：

| 触发类型 | 时机 | 说明 |
|----------|------|------|
| 会话结束触发 | 用户说"好了"、"先这样"、静默超30分钟 | 检测会话自然结束信号 |
| 重要里程碑 | 完成关键任务、收到重要结论 | 有价值内容立即记 |
| 每日定时兜底 | 21:00-22:00 | 保证每天至少一条，21:00避开通勤/饭点 |

**取消**固定时段的自动消息提取（08:00 / 16:00 / 23:00）。

---

## 3. 避免重复记录

### 机制

1. **每个自然日只生成 1 个文件**（`memory/YYYY-MM-DD.md`）
2. **写入前先检查**：文件存在则追加到对应 section，不存在则新建
3. **Section 锚点去重**：以 `## 今日进展` / `## 重要决策` / `## 经验教训` / `## 待跟进` 为锚点，已存在相同内容则跳过
4. **每日首次触发时做 diff**：新内容才写入，重复内容跳过

### 实现要点
- 写入前读取当日文件，提取已有 section 内容做比对
- 用内容 hash 或首行比对快速检测重复
- 追加模式：只在已有 section 下添加新条目，不覆盖历史记录

---

## 实施优先级

1. **立即**：停止 08:00 / 16:00 的自动消息提取，改为每日 21:00 一次性触发
2. **短期**：改造记录格式生成逻辑，从"转储原始消息"改为"合成关键结论"
3. **中期**：加入会话结束信号检测，实现事件驱动触发
