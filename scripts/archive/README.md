# scripts/archive 说明

*Last updated: 2026-04-27*

这个目录不是“看到 archive 就能全删”。
这里同时包含：

1. **生产保留脚本**（仍被当前任务体系调用）
2. **历史归档脚本**（保留做参考/回滚）
3. **旧版本子目录**（仅做追溯）

## 一、生产保留（不要清理）

| 路径 | 状态 | 原因 |
|---|---|---|
| `backup-check.sh` | **生产保留** | 当前仍被 crontab 在 `22:05` 调用，用于备份检查 |

> 规则：即使脚本位于 `archive/`，只要仍被 `crontab -l` 或真实运行入口调用，就属于生产保留。

## 二、历史归档（可保留参考，不参与现行运行）

| 路径 | 状态 | 说明 |
|---|---|---|
| `backup-with-retry.sh` | 历史归档 | 早期备份重试方案，当前不作为主入口 |

## 三、旧版本子目录（仅参考）

| 路径 | 状态 | 说明 |
|---|---|---|
| `old-feishu/` | 旧版本 | 老飞书通知方案 |
| `old-session/` | 旧版本 | 旧会话保存方案 |
| `old-stock/` | 旧版本 | 旧股票脚本方案 |

## 四、清理原则

1. **先看真实运行入口**
   - `crontab -l`
   - `openclaw cron list`
   - 运行脚本本身
2. **被实际调用的脚本，不因目录名叫 archive 就清理**
3. **若未来要迁出生产保留脚本，先改调度入口，再移动文件**

## 五、当前结论

- `backup-check.sh`：**继续保留在 archive，但视为生产脚本**
- 其余 archive 内容：**默认按历史参考处理**
